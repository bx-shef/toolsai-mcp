# Права доступа: страница администратора портала

> Last reviewed: 2026-10-16

Кто из сотрудников пользуется ИИ через сервер, кто может менять данные и какие модули портала
подключены — решает **администратор Битрикс24** на странице `<PUBLIC_URL>/admin`, а не `.env` сервера.

## Как это устроено

1. Администратор открывает `<PUBLIC_URL>/admin` (например `https://b24.stuttgart.by/mcp-ai/admin`),
   вводит адрес портала и входит через приложение Битрикс24 — тем же входом, что и сотрудники.
2. Кто вошёл и с какого портала — из ответа OAuth-сервера Битрикс24; администратор ли он —
   штатный `user.admin` от его имени (при входе и при каждом сохранении).
3. На странице три поля:
   - **Кто пользуется MCP** — коды доступа Битрикс24: `AU` все сотрудники, `U7` сотрудник,
     `D3` отдел, `DR3` отдел с подотделами, `G2` группа пользователей (полный список форматов —
     документация `user.access`). Пусто — только администраторы портала.
   - **Кто может менять данные** — те же коды; действует на встроенную запись в задачи
     (создание, правка, статус, чек-лист, комментарии, учёт времени) и на инструменты модулей с
     записью и удалением. Пусто — только администраторы.
   - **Модули портала** — методы-манифесты (`vendor.mcp.tools`, [`MODULE_TOOLS.md`](MODULE_TOOLS.md)).
4. Настройки хранятся у сервера в Redis по `member_id` портала: у каждого портала свои.
5. Проверка — штатный `user.access` от имени сотрудника: отделы с подотделами, группы и «все
   сотрудники» считает сам Битрикс24, мы оргструктуру не повторяем. Администратор портала проходит
   всегда (так работает `user.access`). Ответ живёт 5 минут; сохранение настроек сбрасывает его сразу.
6. Сбой портала при проверке — «нет доступа» и запись в журнал; в кеш не попадает.

Почему настройки у сервера, а не в `app.option` портала: `app.option.set` требует контекст
приложения во фрейме и права администратора — страницы во фрейме у нас нет, а данные те же.
Почему коды, а не выбор мышью: штатный диалог `BX24.selectAccess` работает только внутри фрейма
портала. Страница во фрейме — следующий шаг, формат кодов не изменится.

## Запасной путь — .env

`ALLOWED_USERS`, `WRITE_USERS`, `MODULE_MANIFESTS` в `.env` по-прежнему работают и **добавляются**
к настройкам портала (страница показывает, что открыто из `.env`). Больше не обязательны: без них
вход открыт только администраторам, пока они не настроят доступ на странице.
