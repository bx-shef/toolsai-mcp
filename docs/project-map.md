## Дальше

Источники плана (разбор 2026-10-13): статья Битрикс24 об облачном MCP
(helpdesk.bitrix24.ru/open/26952788), SDK `bitrix24/b24jssdk` 3.0.0, приложения-образцы
`client-bank-alfa-by` и `invoice-from-tasks`, тестовый облачный портал (вебхук владельца).

**Сейчас — владелец**

1. ⏳ Шаг 1 — [`OAUTH_CHECK.md`](OAUTH_CHECK.md). Без него разворот не начинать.
2. ⏳ [`REPO_SETUP_CHECKLIST.md`](REPO_SETUP_CHECKLIST.md), `/mcp/` в `.gitignore` портала (PR в `stuttgart-git/b24`).
3. ⏳ Разворот и nginx — [`DEPLOY_BITRIXVM.md`](DEPLOY_BITRIXVM.md); подключить Claude на пользователе 1.

**Дальше — код, по порядку**

4. ⏳ **Смок на тестовом портале** (по образцу `invoice-from-tasks`, `docs/SMOKE.md`): те же
   запросы, что шлют инструменты, против живого портала через вебхук; адрес — только из
   файла `.env.b24test` (не из окружения), страж списка тестовых порталов, секрет вебхука
   вырезается из ошибок; в CI не идёт. Закрывает главную дыру тестов: подставной Битрикс24
   повторяет только то, что мы о нём знаем. Уже подтверждено вживую: `tasks.task.list`
   отдаёт `{tasks:[…]}` и `total`.
5. ✅ **REST через `@bitrix24/b24jssdk` 3.0.0**, вход оставить своим. SDK даёт лимиты портала
   (2 запроса/с), повторы на `QUERY_LIMIT_EXCEEDED`, `callList`/`batch`, разбор ошибок. Обмена
   кода в SDK нет, а защита refresh у него только внутри экземпляра — поэтому свой refresh
   подключается через `setCustomRefreshAuth`, сохранение — `setCallbackRefreshAuth`. Ловушки
   из `client-bank-alfa-by`: `getData()` теряет `total`/`next`; код ошибки — в `getErrors()`;
   повторы на сетевом сбое для записи выключить. Решение владельца: зависимость (`axios`,
   `luxon`) против готовых лимитов.
6. ⏳ **Реестр REST-методов** `docs/REST_METHODS.md` + гард в `tests/repo.test.ts`: метод в
   коде без строки в реестре — красный тест (как в `invoice-from-tasks`).
7. ⏳ **Домен портала из ответа OAuth**: сверять хост `client_endpoint` с `B24_PORTAL_URL`, а
   не верить полю `domain` (`verifyInstallMember.ts` в образцах).
8. ⏳ **Отзыв доступа**: страница «Мои подключения» с «Закрыть доступ» (удаляет наши токены и
   токены Битрикс24 сотрудника) и то же для администратора. В облачном MCP это штатно.
9. ⏳ **Включение по разделам**: администратор выключает группу инструментов (CRM, задачи)
   без выката — по образцу сторонних MCP в Маркете.
10. ⏳ **Звонки, оценки и теги `shef.toolsai`** — после проверки, где модуль их хранит на портале.
11. ⏳ **Запись (шаг 5)**, как в облачном MCP: запрос → показать «было/стало» → явное
    подтверждение → выполнить → журнал. Свой список сотрудников, удалений нет.
12. ⏳ Позже: токен в `Authorization` для клиентов без OAuth (n8n, Yandex AI Studio) —
    короткий, отзываемый, на сотрудника. Сверить имена инструментов с облачным
    `mcp.bitrix24.tech` (`tools/list`).
