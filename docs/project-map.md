# Карта проекта: что это / готово / не готово / дальше / мешает

> Last reviewed: 2026-10-14

Обновляется при каждом мерже (навык `merge-pr`). Задание — `bx-shef/toolsai`, `docs/private/mcp-box.md`.

## Что это

Свой MCP-сервер: ИИ-клиент (Claude, ChatGPT, Cursor) работает с данными **любого** Битрикс24 —
облачного или коробочного — от имени конкретного сотрудника и только в рамках его прав. Свои модули
портала добавляют в него свои инструменты через манифест. Нужен владельцу в повседневных задачах —
независимо от облачного MCP Битрикс24 (сравнение — [`COMPARISON.md`](COMPARISON.md)).

## Готово

Проверено тестами (65) и живым прогоном на тестовом облачном портале (`npm run smoke`,
[`SMOKE.md`](SMOKE.md)). На коробке — ничего (см. «Мешает»).

## Не готово

- **На коробке не проверено ничего**: вход, адрес портала (не ведёт ли во внутреннюю сеть с VM),
  своя область прав модуля в правах приложения, пример PHP из `MODULE_TOOLS.md`.
- Отзыв доступа сотрудником и администратором («Мои подключения»).
- Общий лимит запросов на сотрудника; хвосты ревью — [#2](https://github.com/bx-shef/toolsai-mcp/issues/2)
  (digest образов, шифрование access, блокировка refresh между процессами).
- Ответы длинные: пустые поля, ID вместо имён (стадия, ответственный, контакт).
- Встроенной записи нет (запись — только через модули).
- Реестр REST-методов с гардом (`docs/REST_METHODS.md`, как в `invoice-from-tasks`).

## Дальше — по порядку

1. **Коробка** — [`OAUTH_CHECK.md`](OAUTH_CHECK.md), разворот — [`DEPLOY_BITRIXVM.md`](DEPLOY_BITRIXVM.md):
   вход, `make audit`, подключить Claude на сотруднике 1.
2. **Манифест модуля базы знаний** `shef.mcp.tools`: поиск, чтение, создание, правка, удаление
   статей, новости, предпросмотр. Проверить, видна ли область модуля в правах приложения.
3. **Короче ответы**: без пустых полей; имена вместо ID.
4. **Остатки и цены** — штатными методами каталога, если они есть на коробке (сверить).
5. **Отзыв доступа** и **общий лимит** на сотрудника.
6. Звонки, оценки и теги `shef.toolsai` — после проверки, где модуль их хранит.
7. Встроенная запись: «было/стало» → подтверждение → журнал; свой список сотрудников.
8. Позже: включение инструментов по разделам без выката; токен в `Authorization` для клиентов
   без OAuth (n8n, Yandex AI Studio); сверить набор с облачным MCP (`tools/list`).

**Сознательно не берём из образцов**: фрейм и `b24ui` (страниц в портале нет), Postgres и
очереди (Redis хватает), визуальные тесты, `paths-ignore` в CI (образ нужен у каждого коммита `main`).

## Мешает

- **Доступ к коробке** по публичному адресу (можно тестовый стенд): туда ходит наш сервер.
- **Приложение Битрикс24** с `client_id` и `client_secret`: локальное — для одного портала,
  из партнёрского кабинета — для многих. Заводит владелец.
- **Репозиторий модуля базы знаний** — чтобы написать в нём манифест.
- Тестовый вебхук облачного портала истекает через пару дней — живой прогон потом нужен новый.
