# Карта проекта: что это / готово / не готово / дальше / мешает

> Last reviewed: 2026-10-16

Обновляется при каждом мерже (навык `merge-pr`). Задание — `bx-shef/toolsai`, `docs/private/mcp-box.md`.

## Что это

Свой MCP-сервер: ИИ-клиент (Claude, ChatGPT, Cursor) работает с данными **любого** Битрикс24 —
облачного или коробочного — от имени конкретного сотрудника и только в рамках его прав. Свои модули
портала добавляют в него свои инструменты через манифест. Нужен владельцу в повседневных задачах —
независимо от облачного MCP Битрикс24 (сравнение — [`COMPARISON.md`](COMPARISON.md)).

## Готово

Проверено тестами, живым прогоном на тестовом облачном портале (`npm run smoke`,
[`SMOKE.md`](SMOKE.md)) и **на коробке `b24.stuttgart.by` (2026-10-16)**: развёрнуто на BitrixVM,
вход через портал, задачи и дела CRM в Claude, журнал, автообновление включено.

## Не готово

- На коробке не проверено: инструменты своего модуля (своя область прав в правах приложения,
  пример PHP из `MODULE_TOOLS.md`); сделки, лиды, контакты, компании — проверены только задачи и дела.
- Отзыв доступа сотрудником и администратором («Мои подключения»).
- Общий лимит запросов на сотрудника; хвосты ревью — [#2](https://github.com/bx-shef/toolsai-mcp/issues/2)
  (digest образов, шифрование access, блокировка refresh между процессами).
- Ответы длинные: пустые поля, ID вместо имён (стадия, ответственный, контакт).
- Встроенная запись — задачи и встреча в календаре; правка и удаление событий, CRM на запись — нет.
- Документация — локальный клон `bitrix-tools/b24-rest-docs` (`npm run docs:bitrix`); MCP `b24-dev-mcp` отдавал неверную форму параметров у методов задач REST v3 (без `fields`) — сверять с клоном.
- Реестр REST-методов с гардом (`docs/REST_METHODS.md`, как в `invoice-from-tasks`).

## Дальше — по порядку

1. На серверах: `make self-update && make up`; в приложении Битрикс24 добавить права `calendar`, `im`;
   администратору — открыть `<PUBLIC_URL>/admin` и раздать доступ кодами (`docs/ACCESS.md`).
2. **Страница настроек во фрейме портала**: штатный выбор `BX24.selectAccess` вместо ввода кодов.
3. **Свой модуль портала** (новости, предпросмотр, остатки) — манифест `shef.mcp.tools`, включается на `/admin`; база знаний теперь штатная (`note_*`).
4. **Короче ответы**: без пустых полей; имена вместо ID.
5. **Инструменты для типовых решений Вайбкода** — план [#20](https://github.com/bx-shef/toolsai-mcp/issues/20), по issue на PR.
6. Отзыв доступа сотрудником и общий лимит запросов на сотрудника.
7. Облако — проверка на живом портале; свой домен `mcp-bel.bx-shef.by` (отложено).

**Сознательно не берём из образцов**: фрейм и `b24ui` (страниц в портале нет), Postgres и
очереди (Redis хватает), визуальные тесты, `paths-ignore` в CI (образ нужен у каждого коммита `main`).

## Мешает

- **Приложение из партнёрского кабинета** — для других порталов (локальное на `b24.stuttgart.by` есть).
- **Репозиторий модуля базы знаний** — чтобы написать в нём манифест.
- Тестовый вебхук облачного портала истекает через пару дней — живой прогон потом нужен новый.
