# Шаг 1: проверить OAuth локального приложения на портале

> Last reviewed: 2026-10-16

**Зачем.** Вся схема держится на том, что коробка умеет полный OAuth: сотрудник входит на
портале, код меняется на токены через облачный сервер Битрикс24. Если портал не зарегистрирован
или не ходит наружу, работать не будет. Проверить — до разворота сервера. Делает владелец
(действия на боевом портале).

## 1. Локальное приложение

Портал → «Разработчикам» → «Другое» → «Локальное приложение»:

- тип — серверное, **«Использует только API»**;
- путь обработчика — `https://b24.stuttgart.by/mcp-ai/oauth/callback` (туда портал вернёт сотрудника);
- права (scope) — `crm`, `task` (задачи REST v2), `tasks` (задачи REST v3), `user_brief` («кто я»),
  `userfieldconfig` (описание пользовательских полей — чтобы модель видела названия полей `UF_*`),
  `calendar` (календарь), `im` (комментарии новых задач живут в чате задачи), `note` (база знаний), `timeman` (рабочее время), `disk` (Диск), `catalog` (товары);
- сохранить и записать `client_id` (`local.…`) и `client_secret` — их потом в `.env` сервера
  (`B24_CLIENT_ID`, `B24_CLIENT_SECRET`). Секрет никуда не пересылать.

## 2. Вход руками — до сервера

Сервера ещё нет, поэтому код ловим глазами: портал вернёт браузер на путь обработчика, страница
будет 404 — это нормально, нужна адресная строка.

1. В браузере, где вы вошли в портал:
   `https://b24.stuttgart.by/oauth/authorize/?client_id=<client_id>&state=check1`
2. Адресная строка после перехода: `…/mcp-ai/oauth/callback?code=…&state=check1&domain=…&member_id=…&scope=…&server_domain=…`.
   Записать `server_domain` и `scope`. Код живёт **30 секунд** — сразу шаг 3.
3. На VM портала (или любой машине):

```bash
curl -s "https://<server_domain>/oauth/token/?grant_type=authorization_code&client_id=<client_id>&client_secret=<client_secret>&code=<code>" | jq 'del(.access_token, .refresh_token)'
```

   Ждём `client_endpoint` = `https://b24.stuttgart.by/rest/`, `expires_in`, `status`.
   Чтобы проверить REST — тот же запрос без `jq 'del…'`, затем
   `curl -s "https://b24.stuttgart.by/rest/user.current.json?auth=<access_token>" | jq .result.ID`.

## 3. Что прислать агенту

| Что | Значение |
|---|---|
| `server_domain` из шага 2 | |
| `scope` из шага 2 | |
| Ответ шага 3 без токенов (поля и `status`) или текст ошибки | |
| `user.current` вернул ваш ID | да / нет |

Токены и секрет не присылать. Если `server_domain` не `oauth.bitrix.info` и не
`oauth.bitrix24.tech` — назвать: его надо добавить в `B24_OAUTH_SERVERS`.

## Если не вышло

| Видно | Что значит |
|---|---|
| Портал пишет, что приложение не найдено | не тот `client_id` или приложение не сохранено |
| Возврата на обработчик нет | путь обработчика в приложении не тот — сверить с шагом 1 |
| Шаг 3: `invalid_grant` | прошло больше 30 секунд — повторить шаг 2 быстрее |
| Шаг 3: таймаут или ошибка сети | с машины нет выхода к `server_domain` |
| Шаг 3: ошибка про лицензию или регистрацию портала | коробка не связана с облаком Битрикс24 — схема в нынешнем виде не работает, решать с владельцем |
