# Ревью PR: /code-review + панель из пяти

> Last reviewed: 2026-10-13

Источник правил — `docs/AGENT_RULES.md` §3. Этот навык — порядок действий.

## 1. Подготовка

1. `git fetch origin main && git merge origin/main` в ветку PR (не rebase чужой ветки). Конфликты —
   решить, затем `npm run typecheck && npm run build && npm test`.
2. Написать **простым языком**, о чём PR: что делает и зачем, в 3–6 строк.

## 2. Запуск — одновременно

- `/code-review` по диффу PR.
- Пять агентов **Sonnet** одним сообщением (параллельно), каждому — своя роль и общие условия:

| Роль | Задача |
|---|---|
| Документация и Skill | `docs/`, `README.md`, `CLAUDE.md`, `.claude/skills/` — точность против кода, работают ли команды (особенно `DEPLOY_BITRIXVM.md`, `OAUTH_CHECK.md`), ссылки |
| Программист | OAuth-поток (`server/lib/oauth.ts`), токены Битрикс24 и refresh (`server/lib/b24.ts`), инструменты, обработка ошибок, скрипт выката |
| Тестировщик | покрытие и качество тестов, краснеют ли при мутации (только в отдельном `git worktree`); проверено ли на живом портале то, что подставной Битрикс24 не ловит |
| Безопасность | PKCE, redirect_uri, одноразовость кодов, хранение токенов, данные в логах, права сотрудника (никакого обхода), порт 127.0.0.1, nginx, supply chain |
| Технический директор | изменение целиком: объём, нагрузка на VM портала, что потребует рук на сервере, в nginx или на портале |

Общие условия — в промпт каждому:

- Начни с диффа (`git diff origin/main...HEAD --stat`), не грузи всё дерево.
- Рабочее дерево общее: чужая правка — сосед, не откатывать.
- Код меняет только тестировщик и только в отдельном `git worktree`; откат — из копии, никогда
  `git checkout --`.
- Сообщай находки (файл:строка, что, почему, как исправить, насколько уверен) — не чини.
- Поведение Битрикс24 — сверять с документацией (b24-dev-mcp) и `docs/OAUTH_CHECK.md`, не по памяти.
- Данные портала в ревью не цитировать.

## 3. Отчёт владельцу — по-русски, коротко

Блок на ревьюера: **кто — что — почему важно — как исправить**. Отдельной строкой — находки,
которые берёшь, и которые нет (с причиной и замером).

## 4. Исправления

- Всё правится **в этом PR**. Находка просится в отдельный issue/PR — спросить владельца.
- Исправление гарда — с тестом, который краснеет при мутации.
- После исправлений: `npm run typecheck && npm run build && npm test && shellcheck deploy/bitrixvm/mcp-deploy.sh`,
  пуш. Доработка существенная — панель заново.
